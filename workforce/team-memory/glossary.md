# Glossary — ACME Bonsai

Canonical vocabulary used across all teams. When in doubt about what a term means in our context, this file is the answer. When this file contradicts a team's local usage, this file wins; teams update their files.

---

## Business + Brand

**ACME Bonsai** — Our canonical brand name. Used everywhere customer-facing and internally. Not abbreviated unless necessary; never "AB" in customer materials (acceptable in internal Discord shorthand only).

**Closed family tree farm** — Our supply story. We grow our own; we don't import or wholesale-purchase. Differentiator vs other bonsai retailers.

**coastal** — Geographic + cultural reference to the Harbor City coastal region. Used for atmospheric texture in brand voice; never as a generic synonym for "southern".

**Zone 9a** — Climate classification for Harbor City. Humid subtropical. All care advice is calibrated for this zone. If serving customers outside Zone 9a, calibrate accordingly.

**Churn** — Subscription cancellation. Service-quality-driven churn target: < 5% annual.

## Operations

**Tree ID** — Format: `acme-tr-{slug}`. Every saleable tree has one. Canonical identifier in the inventory sheet. Used across all workspaces that reference specific trees.

**Inventory sheet** — Google Sheets sheet (env: `INVENTORY_SHEET_ID`) that is the canonical source for tree counts. Atomic per-row updates only. Tally + Grove both write.

**Safety threshold** — Per-species/size minimum count below which Tally alerts. Set in inventory sheet per row.

**Allocation priority** — Order in which inventory commitments are honored: wholesale > rental > local sales > marketing > workshop demo trees.

**Reservation** — Inventory held for a specific customer / order. Carries `hold_until` date.

**Pick list** — Per-route loading manifest. Generated by Tally / Grove for delivery dispatch.

**Route** — Multi-stop van delivery plan. Built by Cedar (retail / rental / subscription) or Miles (wholesale).

**Van** — ACME Bonsai delivery van. The only fulfillment vehicle. No third-party freight.

**Mortality rate** — Trees lost (transitioned to `status = lost`) / denominator over trailing 30 days. Target: < 2%.

## Financial

**Runway** — Months of operating cash at current burn rate. Target: > 180 days (green); 90–180 days (yellow); < 90 days (red, immediate Jane alert).

**Burn rate** — Trailing 3-month average net cash outflow per month.

**Cash position** — Available cash across operating accounts at a point in time.

**Margin floor** — Per-channel minimum gross margin %. Set by Margin (CFO). Discounts below floor require Jane approval.

**Wholesale margin floor** — 35% gross margin (configurable).

**Monthly close** — Day 5 of following month, 6 PM ET target. Zero unexplained variances at `cfo_review`.

**Variance** — Actual vs budget/forecast difference. Material if abs > 15%.

**Refund threshold** — $500. ≤ $500 Poppy (CSM) approval; > $500 Jane approval.

**Discount threshold** — 20% off list (Cash/DoS approval); 25% on wholesale > 100 trees (Cash volume tier); > 25% (Cash + Jane + Margin all three).

**Deposit minimum** — 50% upfront for wholesale contracts, rentals, subscriptions.

## Sales Pipeline

**Lead** — Inbound inquiry. Status: `received → qualified → opportunity_created` (or `disqualified`).

**Opportunity** — Qualified pipeline entry with stage + weighted value. Stages: `discovery → proposal → negotiation → committed → won` (or `lost`).

**Quote** — Customer-facing pricing document. Lifecycle: `drafted → cash_review → sent → viewed → accepted` (or `rejected` / `expired`).

**Deal** (Closed Deal) — Won or lost opportunity outcome record.

**Weighted pipeline** — Sum of opportunities * probability. Used for forecasting.

**Renewal window** — 60 days before subscription expiration; Sophia initiates outreach.

**Save** — Concession to retain at-risk customer. Major-account saves require Jane approval.

## Customer Service

**Ticket** — Customer support inquiry. Owned by Pearl initially; routed to Oakley / Maple as needed.

**SLA — First Response** — < 2 hours during business hours.

**SLA — Resolution** — < 24 hours for most issues.

**Care consultation** — Tree health diagnostic + prescription. Owned by Maple.

**Health check-in** — Proactive customer outreach. Triggered by signals (CSAT dip, activity drop, post-delivery, post-workshop).

**Species pattern** — ≥ 3 customers with same species + same symptoms in 30 days. Flagged to Tally + Poppy.

**Issue pattern** — ≥ 3 customers with same issue in 7 days. Flagged to responsible operating team.

**Persistent unresolved** — Customer contacted > 3 times about same issue. Escalated to Poppy.

**Legal trigger** — Customer message containing "lawyer", "lawsuit", "consumer protection", or similar. Immediate Jane escalation; no automated response.

## Technology

**Spec** — Technical design doc for a feature. Drafted by Pixel / Forge / Bastion; approved by Allen + requester.

**PR** — Pull Request. GitHub canonical; tracked in CTO ledger.

**Release** — Production deploy. Idempotency key; backup verified within 26h; rollback plan documented; not Friday; not pre-campaign.

**Incident** — Production issue. SEV-1 (full down / > 50% degraded) / SEV-2 (significant) / SEV-3 (partial) / SEV-4 (minor).

**MTTR** — Mean Time to Resolution. Per-SEV target tracked.

**SLO** — Service Level Objective. Uptime: 99.9%. API p95 latency: < 500ms. Error rate: < 1%.

**Tech debt** — Tracked with explicit interest rate (cost of carrying per month) + principal estimate.

**Auto-rollback** — Bastion triggers if post-deploy error rate > baseline + 2% sustained 5 min.

## Idempotency Keys

Format varies by team. Pattern: `acme-{team-prefix}-{entity-id}-{action-kind}-{attempt}`.

Examples:
- Wholesale contract send: `acme-{contract_id}-docusign-{attempt}`
- Customer support reply: `acme-care-{ticket_id}-reply-first-{attempt}`
- Production deploy: `acme-tech-{release_id}-deploy-{attempt}`
- Post publish (CMO): `acme-post-{date}-{platform}-{vertical}-{kind}-{instance}-{platform}-{date}-{attempt}` (legacy CMO pattern)

Before any outbound side-effect, check the team's ledger for an existing entry with the same key.
